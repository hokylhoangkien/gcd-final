# G5 multi-backbone geometry on Stanford Cars

This exploratory analysis reuses the G1 query and bank IDs, common pair pools and checkpoint-specific classifier slots. DINOv2 ViT-B/14 uses the same RGB images, bicubic short-edge resize to 256 and center crop to 224 as DINOv1. Both use ImageNet RGB normalization. DINOv2 final CLS is L2-normalized and cached once for both checkpoints. JSON records the official release URL, locked SHA256, local source digest and feature-cache provenance.

M0 uses fine-tuned DINOv1 cosine. M1 uses frozen pretrained DINOv1 cosine. M2 uses frozen DINOv2 cosine. M3 averages the M0 and M2 cosine matrices at equal weight. M4 uses the M2 alternative-minus-current slot support margin for detection. M5 uses one minus top-10 neighborhood Jaccard agreement between M0 and M2. M4 and M5 keep M0 retrieval.

Flags use fixed global 10/20/40% coverage with query-ID tie breaking. Old/New precision and recall are conditional on the same global flags. Destinations use bank-only Hungarian semantic alignment. Recovery and regression are versus M0 top-1 on wrong-source queries. For epoch 150, stable errors are wrong under both checkpoint alignments with unchanged slots after label-blind bank matching, as in G4. Stable-error AUROC includes all other queries as negatives. JSON also gives error AUROC restricted to unchanged slots and stable-error recall at fixed coverage.
